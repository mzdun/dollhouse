# AGENTS.md

Guidance for coding agents (and humans) working on **dollhouse**.

> Your house, your furniture, in one place

The project was generated by [Project Flow](https://pypi.org/project/proj-flow/) 0.37.1. Building, testing and packaging go through the `flow` wrapper, which runs proj-flow steps one after another. Use the wrapper; do not call CMake or Conan directly unless you are debugging a single step.

## Tools

| Tool | Role |
| ------ | ------ |
| Python 3 | runs `.flow/flow.py`, which installs `proj-flow` into `.venv/` on first use |
| proj-flow | task runner: `./flow <command>` |
| CMake 4.2+ | build system; presets live in `CMakePresets.json` |
| Conan 2 | C++ dependencies from `conanfile.txt` (GoogleTest, SDL3, Dear ImGui and others); mbits-args comes from the `external/args` submodule |
| Ninja / MSBuild | generator on Linux / Windows (see `build_generator` in `.flow/matrix.yml`) |
| GCC, Clang, MSVC | compilers; C++23 with extensions off |
| clang-format | code style, configured in `.clang-format` |
| cpplint | C++ lint in CI, configured in `CPPLINT.cfg` |

### Building on Ubuntu

On Linux, SDL3 depends on Conan's `*/system` packages. These install nothing: they only check that the distribution's development packages are present. Install those packages with `sudo` before the first `config`. Which packages you need depends on the video backend chosen in `[options]` of `conanfile.txt`.

**X11** (the current setting, `sdl/*:wayland=False`) needs *libudev/system*, *opengl/system* and *xorg/system*. The last one checks the whole X.org stack at once, so the list is long:

```bash
sudo apt install libgl-dev libudev-dev libx11-xcb-dev libfontenc-dev libice-dev libsm-dev libxaw7-dev \
  libxcb-composite0-dev libxcb-dri2-0-dev libxcb-dri3-dev libxcb-ewmh-dev libxcb-glx0-dev \
  libxcb-icccm4-dev libxcb-keysyms1-dev libxcb-present-dev libxcb-randr0-dev libxcb-res0-dev \
  libxcb-shape0-dev libxcb-sync-dev libxcb-util-dev libxcb-xfixes0-dev libxcb-xinerama0-dev \
  libxcb-xkb-dev libxcomposite-dev libxcursor-dev libxdamage-dev libxext-dev libxfixes-dev \
  libxi-dev libxinerama-dev libxkbfile-dev libxmu-dev libxmuu-dev libxpm-dev libxrandr-dev \
  libxrender-dev libxres-dev libxss-dev libxt-dev libxtst-dev libxv-dev libxxf86vm-dev uuid-dev
```

**Wayland only** needs *libudev/system*, *opengl/system*, *egl/system* and *xkeyboard-config/system*. Conan builds `wayland` and `xkbcommon` itself; the `xkbcommon` recipe needs Conan 2.18 or newer. Turn X11 off in both SDL and xkbcommon, or xkbcommon brings *xorg/system* back:

```ini
[options]
sdl/*:x11=False
sdl/*:wayland=True
xkbcommon/*:with_x11=False
```

```bash
sudo apt install libgl-dev libudev-dev libegl-dev xkb-data
```

To have **both** backends, set `sdl/*:wayland=True` and leave X11 on, then install both lists.

## Common commands

On Windows use `flow` (or `flow.cmd`) instead of `./flow`.

```sh
./flow list --all          # commands, aliases, run steps and matrix keys
./flow config --dbg        # Conan install + CMake configure, Debug
./flow build --dbg         # build Debug
./flow test --dbg          # build and run tests, Debug
./flow test --both         # same, for Debug and Release
./flow test --sane         # Debug with AddressSanitizer and UBSan
./flow test --tsan         # Debug with ThreadSanitizer (GCC and Clang only)
./flow verify --rel        # build, test, sign, pack and install-check, Release
./flow run -s Build,Test -D build_type=Debug compiler=clang
./flow run --dry-run --dbg # print what would run, do nothing
```

- `config`, `build`, `test` and `verify` are aliases defined in `entry` of `.flow/config.yml`; each runs a fixed list of steps.
- `-D key=value` filters the build matrix in `.flow/matrix.yml` (keys: `compiler`, `build_type`, `sanitizer`, `os`). `sanitizer` is `address`, `thread` or `off`. `--dbg`, `--rel`, `--both`, `--sane` and `--tsan` are shortcuts for common `-D` sets.
- The sanitizer builds share `build/debug` with the plain Debug build. After switching between them, run `config` again (e.g. `./flow run -s Conan,CMake,Build --tsan`): `build` alone keeps the previous configuration.
- On Linux, the tests and the Python runs of a ThreadSanitizer build go through `setarch -R`: GCC's TSan does not start with the full ASLR of newer kernels. Run its binaries by hand the same way, e.g. `setarch -R build/debug/bin/shapes-test`.
- `-E w-error=on` turns warnings into errors.
- `-E freethreaded-shapes=on` declares the `shapes` module safe to run without the GIL on the free-threaded CPython. The module is not thread-safe yet, so use it for experiments only; without it, importing `shapes` turns the GIL on.
- `--official` limits the matrix to the release builds listed in `.flow/official.yml`.
- Debug builds measure code coverage (except the ThreadSanitizer one): `DOLLHOUSE_COVERALLS` adds the coverage flags (GCC/Clang) or runs the tests under OpenCppCoverage (MSVC), and the `Test` step builds `DOLLHOUSE_coveralls` instead of running ctest. The pytest suite of `shapes` counts towards the coverage of the module. The report goes to `build/artifacts/coverage/coveralls_<os>-<build_type>-<compiler>.json`. With `NO_COVERAGE` set in the environment (any value), flow drops the coverage from every build; switching it on or off needs a new `config`.

Build trees go to `build/debug` and `build/release`. Test reports (JUnit XML) are written under `build/<config>/test-results/`.

## Layout

- `.flow/`
  - `flow.py` bootstraps the project: pins proj-flow to 0.38.0 and installs it into `.venv/`
  - `config.yml` lists extensions, run aliases (`entry`), compiler names, CMake variables and shortcuts
  - `matrix.yml` is the build matrix: compiler x build_type x sanitizer x os; `postproc` in `config.yml` trims it further for CI, e.g. ThreadSanitizer runs on one Ubuntu runner only
  - `official.yml` filters the matrix down to release builds (`--official`)
  - `cmake/` holds CMake modules; `common.cmake` has `add_project_test()` and `add_win32_icon()`; `coverage.cmake` has `add_to_coverage()`, used in `libs/CMakeLists.txt` to list the libraries measured
  - `packages/` holds the CPack setup (TGZ/DEB on Linux, ZIP/WiX on Windows)
  - `extensions/dollhouse/` holds project-local proj-flow extensions (Python), e.g. the Icons step
- `flow`, `flow.cmd` are wrappers calling `.flow/flow.py`
- `CMakeLists.txt` is the top-level project; its options use the `DOLLHOUSE_` prefix
- `CMakePresets.json` has debug/release presets, with Ninja, Makefile and Visual Studio variants
- `conanfile.txt` lists Conan requirements
- `libs/`, with `CMakeLists.txt` adding the subdirectories below
  - `libdollhouse/`
    - `include/dollhouse/` public headers
    - `src/` sources, private headers and `version.hpp.in`
    - `tests/` GoogleTest sources, listed in `TEST_SRCS` of `libdollhouse-test`
  - `app/src/main.cpp` is the entry point, linking `libdollhouse`
- `external/args/` submodule ([mbits-libs/args](https://github.com/mbits-libs/args), branch `feat/hooks`), added with `add_subdirectory()` as `mbits::args`, until a release has the help, error and exit hooks
- `tools/coveralls/` submodule ([mbits-libs/coveralls](https://github.com/mbits-libs/coveralls), branch `coverage-tests`) turning gcov/llvm-cov/OpenCppCoverage results into Coveralls reports
- `.covcollect.in`, `.covmodules` configure the local [`cov`](https://github.com/mzdun/cov) tool; the first one is filled in by CMake as `build/<config>/.covcollect`
- `data/icons/` SVG sources of the application icon; `data/assets/` generated icons and installer artwork
- `.github/workflows/` `build.yml` (matrix build) and `linter.yml`; `.github/linters/` configs used by super-linter
- `.github/ISSUE_TEMPLATE/` bug report and feature request forms; `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`
- `COMMITS.md` commit message rules

## Working with the code

- Namespace: `dollhouse`. Include project headers as `#include <dollhouse/...>`.
- `version.hpp` is generated by CMake from `version.hpp.in` into the build tree. Edit the `.in` file, never the generated header. The version itself comes from `project(... VERSION ...)` in `CMakeLists.txt`.
- New source files go to the `SRCS` list and new test files to the `TEST_SRCS` list in the matching `CMakeLists.txt`.
- Put the logic into `libs/libdollhouse`, where it can be tested; keep `libs/app` a thin entry point. A new library goes into its own `libs/<name>/` directory, added with `add_subdirectory()` in `libs/CMakeLists.txt`.
- New C++ dependencies go to `[requires]` in `conanfile.txt` and then `find_package()` + `target_link_libraries()` in CMake.
- Never keep an owned C pointer from SDL or Dear ImGui bare. Wrap it in a `std::unique_ptr` alias whose deleter calls the matching destroy function given as a template argument, so the deleter is an empty type, and `static_assert` that the alias is the size of the raw pointer. GPU resources released through their device (`SDL_ReleaseGPU*(device, ptr)`) keep the device next to the pointer instead. See [Handles](docs/ui-framework-analysis.md#handles).
- SDL is called only from `libs/backends/`; the other libraries stay free of it, so they can be tested without a window. The layers are in [docs/project-structure.md](docs/project-structure.md).
- Compiler flags for every target come from `DOLLHOUSE_ADDITIONAL_COMPILE_FLAGS` and `DOLLHOUSE_ADDITIONAL_LINK_FLAGS` set in `.flow/cmake/common.cmake`.
- Format changed C++ files with clang-format before committing.

## Project Flow

- The proj-flow version is pinned in `PROJ_FLOW_VERSION` of `.flow/flow.py`. Additional Python packages needed by local extensions go to `REQUIREMENTS` in the same file.
- Steps come from the extensions listed in `extensions` of `.flow/config.yml`. A local extension under `.flow/extensions/` becomes active once its module is added there (for example `dollhouse.icons` for the Icons step, which needs ImageMagick).
- `./flow <command> --help` documents every command and its arguments.

## Continuous integration

`build.yml` asks `./flow github matrix` for the list of builds and runs `./flow run` on each of them. Keep the local matrix in `.flow/matrix.yml` and the CI matrix in sync by changing the matrix, not the workflow.

Each Debug build uploads its part of the coverage to Coveralls as a parallel job, and the `coveralls-done` job closes the Coveralls build and comments the summary on the PR. Both need the `COVERALLS_REPO_TOKEN` secret; without it, nothing is sent and the reports are only kept as the `Coverage` artifact.

Releases are cut by hand: a maintainer runs `./flow github release`, which reads the commits since the last tag, bumps the version, updates the changelog and drafts a GitHub release. Pushing its `v*` tag starts `build.yml`, which attaches the packages and publishes the release. Do not bump versions or edit the changelog by hand.

## Commits

Commit nothing unless asked to.

Do not add attribution of any kind: no `Co-Authored-By:`, `Generated with …` or similar trailers or footers in commit messages, PR descriptions, issues or comments, and no tool names or links in their place. Commits are authored by the person running the agent.

Follow [COMMITS.md](COMMITS.md): commit messages use Conventional Commits, and the commit history is the source of version bumps and the changelog. Keep one logical change per commit.
